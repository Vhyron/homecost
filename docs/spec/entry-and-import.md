# CLI entry, managed lists, and CSV import

This is the normative home for I-01–I-09 and I-11–I-14. Requirement IDs remain stable for task and test references. Settings behavior is in [operations](operations.md).

## Command reference

| Command | Purpose |
|---|---|
| `homecost init` | Create the database and seed default categories and payment methods; vendors start empty. |
| `homecost add` | Guided entry for one expense. |
| `homecost import FILE.csv` | Import a CSV batch. |
| `homecost list [--category CATEGORY] [--payment-method METHOD]` | List expenses with their IDs; filter by category or payment method, including `unassigned`. |
| `homecost edit ID` / `homecost delete ID` | Correct or permanently remove one expense. |
| `homecost categories list`, `homecost categories add`, `homecost categories rename OLD NEW`, `homecost categories remove NAME` | List or manage categories. |
| `homecost vendors list`, `homecost vendors add`, `homecost vendors rename OLD NEW`, `homecost vendors remove NAME` | List or manage vendors. Vendors can also be added during guided entry. |
| `homecost payment-methods list`, `homecost payment-methods add`, `homecost payment-methods rename OLD NEW`, `homecost payment-methods remove NAME` | List or manage payment methods. |
| `homecost --help` | Show command help. |

## Entry and CSV requirements

| ID | Requirement |
|---|---|
| I-01 | CLI entry and CSV import use the same service validation. Test: `test_guided_entry_and_csv_import_share_service_validation`. |
| I-02 | `homecost add` is guided entry for one expense, prompting in this order: paid date, amount, category, payment method, vendor, cost month, bill date, and quantity (only when the category has a unit). Category and payment method are numbered choices starting at 1; an invalid or out-of-range answer is rejected with a clear message and re-prompted, never silently mapped to a choice. The category prompt includes an add-new-category option that runs the same flow as `homecost categories add`, then offers the refreshed list. The vendor prompt offers choosing an existing vendor, `add a vendor`, or pressing Enter to leave vendor empty. Optional fields may be skipped; `cost_month` accepts `YYYY-MM` and pressing Enter uses the paid month. Tests: `test_guided_add_uses_service_and_stores_metered_expense`, `test_guided_add_can_add_and_select_existing_vendor`, `test_guided_add_prompts_in_specified_order`, `test_guided_add_rejects_invalid_and_out_of_range_choice_numbers`, `test_guided_add_adds_new_category_in_category_prompt`, `test_guided_add_cost_month_accepts_YYYY_MM`. |
| I-03 | `homecost categories add` creates a category with a name, optional unit, and requires an explicit yes/no answer for monthly-bill-expected; there is no default. Tests: `test_category_add_requires_and_stores_monthly_bill_choice`, `test_category_add_rejects_non_yes_no_answer`. |
| I-04 | Validate the full CSV before writing. If any row is invalid, import nothing and report every problem with its file line number. After duplicate review, import all accepted rows together. Accept a UTF-8 BOM and blank lines. Tests: `test_import_reports_every_invalid_line_and_writes_nothing`, `test_import_writes_all_valid_rows`. |
| I-05 | A CSV header is required; column order is flexible. Required columns: `paid_date`, `amount`. Optional columns: `category`, `vendor`, `cost_month`, `bill_date`, `quantity`, `payment_method`. All amounts use the installation currency. If the category or payment-method column is absent or its value is blank, use the reserved `unassigned` value. A blank vendor stays empty. A nonblank category, vendor, or payment method not in its active managed list rejects the whole import with the row and value; tell the user to add/reactivate the list item or correct the CSV and retry. Tests: `test_import_accepts_bom_flexible_columns_blank_lines_and_defaults`, `test_import_requires_paid_date_and_amount_headers`, `test_import_rejects_unknown_managed_values_with_row_context`. |
| I-06 | Editing an expense is atomic and applies the same validation as creation. Preserve its ID and every field not changed by the edit. Tests: `test_edit_preserves_id_and_unchanged_fields`, `test_invalid_edit_leaves_original_expense_unchanged`, `test_edit_rejects_unknown_expense_id`, `test_edit_command_updates_amount_and_preserves_other_fields`. |
| I-07 | Deleting an expense requires CLI confirmation and permanently removes it. A backup is the recovery path; no audit log is required in v1. Tests: `test_delete_permanently_removes_only_selected_expense`, `test_delete_rejects_unknown_expense_id`, `test_delete_cli_confirms_and_removes_expense`, `test_delete_cli_requires_confirmation`. |
| I-08 | `homecost payment-methods add` adds a method to the managed list. Test: `test_payment_method_add_uses_service`. |
| I-09 | Use the same exact-match duplicate check for manual entry and CSV import. Compare `paid_date`, `cost_month`, `bill_date`, `category`, `amount`, `vendor`, `quantity`, and `payment_method` after defaults and normalization, against saved expenses and earlier rows in the same import. For manual entry, show the matching expense and ask whether to add anyway. For CSV import, pause for each matching row and let the user skip it or import it anyway; then import the accepted rows together and report what was imported or skipped. Tests: `test_manual_entry_warns_and_can_skip_exact_match`, `test_manual_entry_can_confirm_adding_duplicate`, `test_csv_import_reviews_duplicate_in_saved_expenses`, `test_csv_import_reviews_duplicate_rows_in_same_file`, `test_duplicate_lookup_applies_defaults_and_name_normalization`, `test_duplicate_comparison_checks_each_specified_field`. |
| I-11 | Renaming a category, vendor, or payment method changes its name on all existing expenses and for future entries. Confirm and report how many expenses are affected; reject normalized duplicates and reserved `unassigned`. Tests: `test_rename_updates_managed_value_and_all_expenses`, `test_rename_rejects_normalized_duplicates_and_reserved_values`, `test_rename_requires_existing_old_name`, `test_rename_cli_confirms_and_reports_affected_expenses`, `test_rename_vendor_and_payment_method_commands`, `test_rename_cli_cancellation_keeps_value`. |
| I-12 | Removing a category, vendor, or payment method requires confirmation and archives it rather than deleting it. Show how many existing expenses use it; those expenses and reports retain the value. Archived values are unavailable for new manual entries and CSV imports. The reserved `unassigned` values cannot be removed. Tests: `test_archive_preserves_expense_history_and_reports_use_count`, `test_archived_values_cannot_be_used_for_new_expenses`, `test_reserved_unassigned_values_cannot_be_archived`, `test_remove_command_confirms_archive_and_reports_count`, `test_remove_cancellation_does_not_create_or_change_database`, `test_remove_commands_archive_vendors_and_payment_methods`, `test_csv_import_rejects_archived_category`. |
| I-13 | `homecost list --category unassigned` and `homecost list --payment-method unassigned` find expenses with missing classifications. Editing one expense changes only that expense; it does not rename or remove the reserved `unassigned` values. Tests: `test_list_expenses_filters_by_category_and_payment_method`, `test_list_cli_shows_ids_and_filters_unassigned`, `test_list_cli_shows_aligned_table_with_blank_vendor`. |
| I-14 | Managed-list `list` commands show active and archived values. Adding a value that already exists as archived reactivates it instead of creating a duplicate. Tests: `test_adding_archived_values_reactivates_without_overwriting`, `test_managed_lists_show_active_and_archived_values`, `test_list_commands_show_active_and_archived_values`, `test_vendors_add_reactivates_archived_value`. |
